## Что нового в 3.10.2

Версия 3.10.2 — исправительный выпуск после 3.10.0 (отдельного выпуска 3.10.1 не было). Главное: правки клиентов **Shadowsocks** применяются на лету и больше не рвут соединения на порту ([5.6](#56-shadowsocks)); у MTProto появился **лимит незавершённых рукопожатий на IP** ([5.12](#512-mtproto-прокси-для-telegram)); импорт **VMess-ссылок** больше не теряет настройки XHTTP и mKCP ([11.4](#114-outbounds-исходящие-подключения)); Clash/Mihomo-подписка выдаёт **Hysteria2 с обфускацией Gecko** ([10.4](#104-форматы-вывода)); маршрутизация Incy больше не смешивается с заголовками Happ. Ядро прежнее — **Xray-core v26.10.10**, разовых миграций базы нет. Ниже — изменения относительно 3.10.0 по разделам руководства.

### Изменения в разделе 1 — Введение, требования и установка

- **Сборка для Windows теперь называется `3x-ui.exe`** (вместо `x-ui.exe`) и несёт сведения о версии и значок: «голый» исполняемый файл Go без них чаще вызывает ложные срабатывания антивирусов.

### Изменения в разделе 3 — Обзор / Дашборд

- **Карточки спонсора в боковой панели больше нет**, а на странице «Спонсоры» показываются только настоящие спонсоры (заглушка «Ваш бренд здесь» — лишь когда список пуст). Данные о спонсорах панель теперь загружает с `raw.githubusercontent.com`, а не с `sponsors.sanaei.dev`: имя, уникальное для 3x-ui, уходило в открытом SNI и позволяло наблюдателю опознать сервер с панелью (#6824).

### Изменения в разделе 5 — Протоколы

- **Shadowsocks: изменения клиентов применяются на лету** ([5.6](#56-shadowsocks)): добавление, удаление, продление, сброс трафика и автоотключение клиента многопользовательского Shadowsocks-inbound'а — правкой в панели, командой главной панели узлу или горячим применением конфигурации — больше не пересоздают inbound. Раньше это закрывало порт и обрывало все живые соединения на нём.
- **MTProto: «Макс. незавершённых рукопожатий на IP»** ([5.12](#512-mtproto-прокси-для-telegram)) — новое поле `settings.pendingHandshakesMaxPerIp` (по умолчанию `0` — выключено): новые подключения с IP, у которого уже столько незавершённых рукопожатий, закрываются. Защищает от флуда рукопожатиями; клиенты за общим IP (NAT оператора) делят этот лимит. Нужен `mtg-multi` 1.16.0 или новее; изменение поля перезапускает процесс `mtg` этого inbound'а.

### Изменения в разделе 10 — Подписки (Subscription)

- **Hysteria2 с обфускацией Gecko в Clash/Mihomo** ([10.4](#104-форматы-вывода)): маска Salamander с диапазоном размеров пакетов выдаётся как `obfs: gecko` с `obfs-min-packet-size`/`obfs-max-packet-size`. Раньше в YAML попадал только пароль — то есть обычный salamander, и клиент не проходил рукопожатие с Gecko-сервером.
- **Маршрутизация Incy отделена от заголовков Happ** (#6810, [10.2](#102-настройки-сервера-подписок)): клиенту Incy, которому уходит строка маршрутизации Incy, заголовки маршрутизации Happ (`Routing-Enable`, `Routing`) больше не отправляются.

### Изменения в разделе 11 — Xray: маршрутизация, outbounds, DNS и расширения

- **Ссылки `vmess://` разбираются полностью** (#6808, #6809; [11.4](#114-outbounds-исходящие-подключения)): при импорте outbound'а, в подписках исходящих и во внешних ссылках клиента читаются поля XHTTP, которые VMess передаёт прямо в JSON ссылки (размещение session/seq, обфускация паддинга, xmux и т. п.), маска Finalmask (`fm`), заголовок и seed mKCP, `mtu`/`tti`. Раньше из такой ссылки получался outbound, который не мог подключиться.
- **Горячее применение охватывает и Shadowsocks** ([11.11](#1111-сохранение-перезапуск-и-автоматические-преобразования)): клиенты Shadowsocks-inbound'а меняются поштучно через API Xray, как у VLESS, VMess, Trojan, Hysteria и MASQUE.

### Изменения в разделе 12 — Узлы (мультипанель, master/slave)

- **Синхронизация трафика с узлами пишет в базу только изменившееся** ([12.7](#127-как-синхронизируются-inbounds-и-клиенты)): раньше раз в 5 секунд перезаписывались записи всех клиентов, о которых сообщил узел, даже простаивающих, а у клиента сразу на нескольких inbound'ах общая запись переключалась туда и обратно. На больших установках заметно падает нагрузка на базу.

### Изменения в разделе 16 — Эксплуатация: бэкапы, логи, обновление, CLI

- **Отчёт о сбое ядра Xray сохраняется целиком** ([16.2](#162-просмотр-логов)): файл `core_crash_*.log` в каталоге логов панели содержит весь отчёт Go — заголовок `panic:`/`fatal error:` и трассировку, а не только первые 7 байт «panic: ». Отчёты, случившиеся в одну секунду, больше не затирают друг друга, а обычные строки лога со словами panic/exception не принимаются за сбой и не пропадают из лога.
