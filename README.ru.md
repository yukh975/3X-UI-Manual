## Что нового в 3.6.0

Версия 3.6.0 обновляет ядро до **Xray 26.7.28** и заметно перерабатывает интерфейс. Главное: страница «Обзор» стала командной панелью (плитки CPU/RAM/Swap/Storage со спарклайнами, новый график TCP/UDP-соединений, боковая панель — раскрывающийся рельс из иконок); TCP-маска **XMC (Minecraft)** теперь требует полноценные профили Mojang (ломающее изменение); подписки научились **определять клиента по User-Agent** и отдавать живой статус через `?format=info`; **API-токены узлов стали «только на запись»**; у писем панели появились поля отправителя **From/имя**; SQLite по умолчанию работает в режиме **WAL**. Ниже — изменения относительно 3.5.0 по разделам руководства.

### Изменения в разделе 1 — Введение, требования и установка

- Ядро **Xray обновлено до 26.7.28** (панель и её дочерний бинарник синхронизированы). Незашифрованный outbound (без TLS/иного шифрования) на публичный адрес по-прежнему отклоняется, но эта проверка **пропускается, если запущенное ядро старше 26.7.11** — чтобы не блокировать конфиг, который ваше ядро на самом деле принимает.

### Изменения в разделе 2 — Вход в панель и безопасность доступа

- **`GET /panel/api/openapi.json` теперь требует аутентификации.** Раньше полная карта админ-API и версия сборки отдавались анонимно (HTTP 200); теперь эндпоинт за общим `checkAPIAuth` (сессия, Bearer-токен или mTLS) — без доступа возвращается 404. Клиенты, отправляющие токен, не затронуты.

### Изменения в разделе 3 — Обзор / Дашборд

- Страница **«Обзор» переработана в командную панель**: сверху панель действий (состояние Xray с версией и текстом ошибки в подсказке, версия/обновление панели, сгруппированные кнопки Restart/Stop, логи/конфиг/бэкап, «История системы»/«Метрики Xray»), при нагрузке — баннер предупреждения (80 % / 90 %).
- Вместо круговых индикаторов — **четыре плитки** CPU/RAM/Swap/Storage: крупный процент, детали и среднее/пик, плюс залитый **спарклайн**. Спарклайны рисуются по окну из 72 точек, при загрузке заполняются из истории `GET /panel/api/server/history/<метрика>/2` и дополняются каждые 2 с; в подсказке — время по часам.
- Два широких графика трендов: **общая скорость** (↑/↓) и **новый график соединений TCP/UDP** (открытые сокеты).
- Убраны: круговые индикаторы, карточка Telegram @XrayUI и Load average (перенесён в «Историю системы»). Полоса «Система» сгруппирована (аптайм Xray | ОС, ОЗУ | потоки панели, IP-адреса с переключателем показа).
- **Боковая панель** стала рельсом из иконок шириной 72 px, раскрывающимся при наведении; ручной переключатель сворачивания убран.

### Изменения в разделе 4 — Inbounds: создание и общие параметры

- Для месячного сброса трафика добавлено поле **«День сброса» (1–31)** — можно выбрать день месяца, в который обнуляется счётчик, вместо фиксированного.

### Изменения в разделе 5 — Протоколы

- **Hysteria — только версия 2.** Схема inbound жёстко приводит `version` к `2` (значение из API/старых панелей исправляется автоматически), а мёртвая схема ссылки `hysteria://` убрана — ссылка всегда `hysteria2://`. «Hysteria2» — это не отдельный протокол, а `hysteria` с `version = 2`.
- Надёжность Shadowsocks: клиент с шифром, записанным под ключом `method` (а не `cipher`), и алиасы вида `aead_*` больше не роняют ядро — имя шифра сверяется с таблицей ядра без учёта регистра, а неизвестное значение считается ошибкой, а не «угадывается».

### Изменения в разделе 6 — Транспорт (Stream Settings)

- XHTTP, поле **`uplinkDataPlacement`**: убран невалидный вариант `query`, добавлен `auto`; подпись значения по умолчанию — **«Default (auto)»**.
- При первом включении XMUX значение по умолчанию **`maxConnections` снижено с 6 до 3** (вслед за ядром 26.7.28); уже сохранённые значения не трогаются.

### Изменения в разделе 7 — Безопасность соединения: TLS, XTLS и REALITY

- **Маска Finalmask XMC (Minecraft) изменена — ломающее изменение.** Вместо списка `usernames` теперь обязателен массив **профилей**, в каждом — `username` (3–16 символов `A-Za-z0-9_`), `uuid` (с дефисами или 32 hex-символа), `texturesValue` и `texturesSignature` (подписанные значения с сессионного сервера Mojang). Прежний откат «по умолчанию Dream» убран. Незаполненную XMC-маску панель **отклоняет при сохранении**; строки из старых панелей / API / бэкапа при генерации конфига **теряют только эту маску** (весь конфиг больше не падает, в лог пишется предупреждение с именем inbound); в форме прежние `usernames` переносятся в заготовки профилей. Пересоберите профили данными с сессионного сервера Mojang, иначе обфускация не работает.
- Поля **Min/Max Client Ver** (REALITY) снабжены подсказками и валидацией формата/диапазона при сохранении; плейсхолдер изменён на `x.y.z`. **Важно:** пустые Min/Max больше не означают «без ограничения» — у проверки есть встроенный нижний порог версии клиента.
- Исправлено: переключение элемента Finalmask в режим «массива» (`rand`) больше не пишет пустой `packet: []`, который ронял весь конфиг (остаток вычищается и из уже сохранённых строк).

### Изменения в разделе 8 — Клиенты

- Новый REST-эндпоинт **`GET /panel/api/clients/get/tgId/:tgId`** — поиск клиентов по Telegram ID (возвращает массив, так как ID не уникален; принимает только положительный ID). Под него добавлен индекс БД.

### Изменения в разделе 10 — Подписки (Subscription)

- **Автоопределение формата по User-Agent** (новая вкладка «Форматы подписки»): `subClashAutoDetect` + `subClashUserAgentRegex` (по умолчанию `(?i)(clash|mihomo)`) отдают Clash-YAML клиентам Clash/Mihomo; `subJsonAutoDetect` + `subJsonUserAgentRegex` (по умолчанию пусто — выключено) отдают JSON-массив; `subJsonAlwaysArray` — всегда массив на явном `/json/`-эндпоинте. Регэкспы — Go RE2, проверяются при сохранении; для применения нужен перезапуск панели.
- Переключатель **«Показывать идентичность в каждой ссылке»** (`subShowIdentityOnAllLinks`): `{{EMAIL}}` / `{{USERNAME}}` остаются в примечании каждой ссылки (токены расхода трафика всё равно только в первой).
- Новый параметр **`?format=info`** — живой статус подписки в JSON (без ссылок, с новым полем **`isOnline`** и дедупом e-mail); шаблоны и страница подписки теперь получают переменную `{{ .isOnline }}`. Параметр **`?view=raw`** и кнопки **«Скачать»** сохраняют JSON/Clash как файл.
- Корректность вывода: WireGuard-клиент экспортирует **все** Allowed IPs (raw-ссылка и `.conf`), а не только первый; Clash-YAML берёт «числовые» short-id / пароли / PSK в кавычки (иначе один прокси обнулял весь провайдер); `flow` VLESS фильтруется и в JSON; пустые переменные примечания не оставляют висячий дефис; Hysteria2 не пишет нестандартный `fm=`; имена внешних ссылок сохраняются в Clash/JSON; заголовок Happ `Routing-Enable` шлётся только когда включён; XHTTP отдаёт старые алиасы полей сессии; `hostHeader` / `path` управляемого хоста применяются к ws/httpupgrade/xhttp; Clash отдаёт `pin-sha256`; raw-генераторы защищены от ошибок 500.

### Изменения в разделе 11 — Xray: маршрутизация, outbounds, DNS и расширения

- **Прямой (freedom) outbound по умолчанию блокирует выход в приватные диапазоны** (`geoip:private`): в начало его `finalRules` добавлено правило `block` — закрыт SSRF-путь к локальным gRPC / метрикам через доменную стратегию AsIs. На апгрейде одноразовый сидер переписывает **только стандартные** `finalRules`; ваши правки сохраняются. Если через прямой outbound вам нужен доступ к LAN / loopback — добавьте явное allow-правило перед блоком.
- Тест маршрута (**Route test**) отклоняет порт вне диапазона, а не заворачивает его.
- Inbound, у которого отфильтрованы все клиенты, отдаёт в конфиге `"clients": []` вместо `null` (косметика для отладки).

### Изменения в разделе 12 — Узлы (мультипанель, master/slave)

- **API-токен узла стал «только на запись».** Чтение узла больше не возвращает сам токен — только флаг `hasApiToken`. При редактировании: пустое поле — **оставить текущий токен**, непустое — заменить, `clearApiToken` — очистить (только для отключённого или mTLS-узла). Подсказка поля: «Оставьте пустым, чтобы сохранить текущий токен».
- Надёжность: «замороженный» трафик ушедшего мастера больше не отключает клиента, который на самом деле в пределах квоты (учитываются только свежие строки); правки fallback у inbound доезжают до узлов; укреплён жизненный цикл MTProto-сайдкара (`mtg-multi`).

### Изменения в разделе 13 — Настройки панели

- Почта (SMTP): новые поля **«SMTP From Address»** (`smtpFrom`) и **«SMTP Sender Name»** (`smtpFromName`). Письмо теперь собирается по RFC 5322 (корректный `From` вида «Имя <адрес>», `Date`, `Message-ID`, тема в UTF-8) — строгие получатели вроде Gmail перестают его отклонять. Пустой `smtpFrom` = использовать логин SMTP (существующие настройки не меняются); неверный адрес отклоняется при сохранении.
- Уведомления: новый порог **`outboundDownThreshold`** (по умолчанию 3, диапазон 1–100) рядом с событием «outbound недоступен» в обоих каналах — Email и Telegram: оповещение шлётся только после N подряд неудачных проверок; `1` — как раньше, по первой неудаче.
- Многие числовые поля получили серую метку **«По умолчанию»**; очистка поля порта больше не сохраняет порт `1` (возвращается прежнее значение — нет блокировки доступа); дата-пикер срока применяется по клику (без кнопки OK, больше не сохраняет `0`).
- Сборка: продакшн-сорсмапы больше не вшиваются в бинарник (размер `dist` упал с ~25 МБ до ~6.7 МБ); для отладки соберите с `XUI_SOURCEMAP=true`.

### Изменения в разделе 14 — Telegram-бот

- **Привилегированные колбэки бота теперь требуют прав администратора** (экспорт бэкапа, массовый сброс трафика, создание клиента, бан-логи и пр.) — важно, если бот добавлен в общий / групповой чат.
- Временное авто-удаляемое сообщение бота больше не сбрасывает состояние пошагового мастера.

### Изменения в разделе 16 — Эксплуатация: бэкапы, логи, обновление, CLI

- SQLite по умолчанию работает в режиме **WAL** — конец шторму ошибок «database is locked» под обычной нагрузкой (применяется автоматически на апгрейде).
- Резервные копии SQLite делаются **онлайн-снимком** (согласованная копия при продолжающихся записях) — для скачивания, миграции и планового Telegram-бэкапа; незавершённые снимки подчищаются при старте.
- PostgreSQL: панель переживает недоступность БД без цикла мгновенных перезапусков (переподключение с backoff, ~70 с суммарно).
- Внешний webhook уведомлений о трафике ограничен таймаутом (~3 с) — «зависший» приёмник больше не тормозит 5-секундный тик трафика и учёт квот.
- Автопочинка при старте: устаревшие строковые `tgId` в настройках inbound исправляются (числовые строковые ID сохраняются) — конец ошибке `cannot unmarshal string into ... tgId`.
