## Что нового в 3.7.0

Версия 3.7.0 добавляет **нативный AmneziaWG** — DPI-устойчивый протокол работает встроенным движком (`amneziawg-go` поверх сетевого стека gVisor), без модуля ядра, без `awg-quick` и без второй панели. Остальное главное: **API-токены получили область действия и срок годности**; продление клиента можно привязать к **календарному дню месяца** и ограничить по количеству; у клиента появились **свой цикл сброса трафика**, **лимит устройств (HWID)** со списком зарегистрированных устройств и **внешние ссылки**, подмешиваемые в его подписку; в подписку можно добавить **балансировщики**; импорт БД **сохраняет настройки этой машины**. Ниже — изменения относительно 3.6.0 по разделам руководства.

### Изменения в разделе 1 — Введение, требования и установка

- **Сборка из исходников требует Go 1.27** (в 3.6.0 было 1.26). Версия ядра Xray не менялась.
- При первом запуске выполняются **автоматические миграции схемы**: цикл сброса трафика и время последней выгрузки подписки у клиента, служебные колонки синхронизации узлов, индекс по `LOWER(email)`, область действия и срок у API-токенов, нормализация внешних ссылок. **Перед обновлением сделайте бэкап базы.**
- Обновление панели больше не удаляет **ваши собственные файлы в `bin/`** (например, вручную положенный `geoip.dat`).
- `update.sh` теперь скачивает файлы **через тот же прокси, что настроен у панели**, — обновление работает там, где прямой выход наружу закрыт.

### Изменения в разделе 2 — Вход в панель и безопасность доступа

- **У API-токена появилась область действия (scope) и необязательный срок годности.** Областей три: `admin` — полный доступ, как и раньше; `monitor` — только чтение и только по списку эндпоинтов состояния (`/server/status`, истории метрик, `/server/getXrayVersion`, `/server/getPanelUpdateInfo`, история метрик узла); `node-sync` — ровно то, что нужно центральной панели для синхронизации (список/добавление/изменение/удаление inbound'ов, операции над клиентами, рестарт Xray). Запрос вне своей области получает **HTTP 403**. Токены, созданные раньше, остаются `admin` — поведение не меняется.
- Срок годности задаётся при создании; после его наступления токен перестаёт аутентифицировать.
- **Замена сохранённого TOTP-секрета теперь требует ввода 2FA-кода** — украденная сессия не может тихо перевесить двухфакторную аутентификацию на свой секрет.
- CLI `x-ui setting -getApiToken` больше **не плодит новые админ-токены**: он ротирует единственный токен `cli-fallback`. Ранее выданные CLI-токены после ротации перестают работать.

### Изменения в разделе 3 — Обзор / Дашборд

- **Боковую панель можно закрепить** («Pin sidebar»/«Unpin sidebar») — рельс из иконок больше не схлопывается после каждого наведения.
- Панель стала **устанавливаемым PWA** (без офлайн-режима: приложение работает только при доступной сети).
- Добавлена плитка **«Uptime»**, а **уровни логов и события доступа теперь локализованы**: Debug/Info/Notice/Warning/Error и DIRECT/BLOCKED/PROXY отображаются на языке интерфейса.
- Появился просмотр **логов AmneziaWG** (`Инструменты → AmneziaWG Logs`): последнее рукопожатие, интерфейс, inbound, endpoint, простой и события.

### Изменения в разделе 4 — Inbounds: создание и общие параметры

- Новый переключатель **«Disable XTLS flow»** (`disableFlow`, только VLESS): отключает автоматическую подстановку `xtls-rprx-vision` для этого inbound'а, даже если транспорт её допускает. На остальных ваших inbound'ах в той же подписке Vision продолжает работать.
- У поля **«Порядок в подписке»** (`subSortIndex`, есть с 3.6.0) появился отдельный узкий эндпоинт `POST /panel/api/inbounds/:id/subSortIndex`. Раньше позицию меняли через `/update/:id`, отправляя inbound целиком вместе со всем списком клиентов, — двое, правящих один inbound одновременно, затирали работу друг друга.
- Закрыта гонка при проверке и занятии порта, а **ошибки валидации формы теперь показываются** вместо молчаливого отказа сохранить.
- **Точнее считается «онлайн» в мультипанели**: клиент, подключённый к узлу, больше не теряется в подсчёте.

### Изменения в разделе 5 — Протоколы

- **Новый протокол — AmneziaWG.** Это WireGuard с обфускацией, устойчивой к DPI. Панель поднимает его **внутри своего процесса** (`amneziawg-go` поверх gVisor netstack), поэтому не нужны ни модуль ядра (DKMS), ни `awg-quick`, ни Docker, ни отдельная панель. Один активный клиент = один peer. Подробности и все поля — в новом подразделе [5.10](#510-amneziawg).
- **Hysteria:** обновление inbound'а с пустым `auth` у клиента теперь отклоняется (раньше это тихо ломало доступ), а клиент Hysteria2, превысивший лимит, **принудительно отключается**, а не продолжает качать до перезапуска.

### Изменения в разделе 7 — Безопасность соединения: TLS, XTLS и REALITY

- **Проверку REALITY-таргета можно выполнить и для адреса в локальной сети.** Раньше SSRF-защита панели просто отказывала; теперь панель предупреждает («Target is reachable but sits on a private/local network»), спрашивает подтверждение и обходит защиту **только для этой одной проверки**. В результат добавлены срок действия сертификата и использованный SNI.

### Изменения в разделе 8 — Клиенты

- **Продление по календарному дню.** Поле **«Renew on day»** (`resetDay`, 1–31): клиент продлевается в этот день каждого месяца в полночь по часовому поясу панели, а не «каждые N дней». Если в месяце нет такого числа, продление происходит в последний день месяца. `0` сохраняет прежний режим интервала.
- **Потолок автопродлений** — поле **«Max renewals»** (`resetMax`): сколько раз автопродление может сработать, прежде чем клиента оставят истечь. `0` — без ограничения. Догоняющие продления за пропущенные периоды тратят по одному на период. Рядом показывается счётчик **«Renewals used»**.
- **Свой цикл сброса трафика у клиента** (`trafficReset` + `trafficResetDay`) — раньше периодический сброс задавался только на уровне inbound'а.
- **Лимит устройств: «HWID Limit»** (`limitHwid`) — максимум зарегистрированных устройств, с которых принимаются запросы подписки; `0` — без ограничения. Рядом появился список **«HWID Devices»**: устройство, ОС и версия, модель, когда впервые и последний раз видели. Устройство можно удалить **по одному** или очистить список целиком — удалённое устройство просто зарегистрируется заново при следующей выгрузке подписки.
- **Внешние ссылки клиента** (вкладка «Links», есть с 3.6.0) обзавелись управлением: строку можно **выключить**, не удаляя (`enable`), задать ей **срок действия** и **префикс имени**, а панель показывает **время последней выгрузки и текст ошибки**, если внешний источник не ответил.
- В таблице клиентов появилась колонка **«Last Subscription Fetch»** — когда подписка выгружалась в последний раз.
- Для клиентов AmneziaWG добавлены поля ключей (**Private/Public/Pre-Shared Key**), **Allowed IPs** (пусто — назначится автоматически) и **Forwarded Ports** — порты и диапазоны, пробрасываемые (DNAT) на этого клиента, например `80, 443, 8000-8100`.
- Исправления: устаревшая строка в журнале IP больше не блокирует сохранение клиента; сводные значки считаются по актуальным данным, а не по снимку `client_stats`; массовая отправка изменений на узлы происходит **после** фиксации транзакции; сохранённые IP-адреса офлайн-клиентов протухают по расписанию.

### Изменения в разделе 9 — Группы клиентов

- Массовый перенос между группами **сообщает о фактически изменённых клиентах и больше не перезапускает Xray**, если менять в конфиге нечего.

### Изменения в разделе 10 — Подписки (Subscription)

- **Страница подписки в браузере не изменилась.** В ходе разработки 3.7.0 её заменяли на нейтральную страницу «это ссылка подписки, скопируйте её», но замену **откатили до релиза**: с мобильного вместо трафика, срока и ссылок показывался пустой экран. В 3.7.0 браузер по-прежнему получает обычную тематическую инфо-страницу, а `?html=1` / `?view=html` и `?format=info` работают как раньше.
- **Балансировщики подписки** — новый раздел настроек «Sub Balancers». Каждый включённый балансировщик добавляется в JSON-подписку как **отдельный профиль**, автоматически выбирающий лучший из endpoint'ов выбранных inbound'ов (в конфиге клиента это `routing.balancers` + `burstObservatory`). Настраиваются примечание, стратегия (**Least load / Least ping / Random / Round robin**), список inbound'ов и позиция в списке подписки; при равных номерах балансировщик идёт после inbound'а.
- **Токены клиента теперь понимают и метаданные подписки.** Раньше `{{EMAIL}}`, `{{ID}}`, `{{SHORT_ID}}`, `{{SUB_ID}}`, `{{TELEGRAM_ID}}` подставлялись только в шаблон ремарки; теперь их принимают заголовок подписки, ссылка поддержки, ссылка на профиль и объявление — можно выдать каждому клиенту персональный заголовок или ссылку в поддержку с его идентификатором.
- **Удалённые правила маршрутизации по URL.** В поля правил для Happ, Incy и Clash можно вписать не только готовый deeplink/инлайн-правила, но и **постоянный HTTPS-URL**: панель обновляет правила в фоне и хранит последнее валидное значение, поэтому запрос подписки никогда не ждёт внешний источник.
- Панель **предупреждает, если настройки salamander (Hysteria2) не дойдут до клиента**.
- Исправления вывода: `tlsSettings.cipherSuites` попадает в JSON-подписку; `mport` сохраняется в ссылках через external proxy; полный remark формируется **один раз на подписку**, а не на каждый credential; в `USAGE_PERCENTAGE` используется полноширинный знак процента.

### Изменения в разделе 11 — Xray: маршрутизация, outbounds, DNS и расширения

- **Outbounds PIA по логину.** Новый раздел «PIA»: вводите логин и пароль Private Internet Access, выбираете страну и сервер — панель сама получает ключ и добавляет готовый WireGuard-outbound. Повторное добавление того же сервера предлагает обновить ключ вместо дубля.
- **Удалённый URL правил маршрутизации** (`remote routing URL`) — набор правил можно держать на внешнем адресе и обновлять централизованно.
- **Выбор клиента прямо в пользовательском правиле**: поле `user` теперь заполняется из списка клиентов, а не вручную.
- **Просмотр категорий geosite/geoip из правила маршрутизации** — не выходя из формы, можно посмотреть, что внутри `geosite:category-ads-all` или `geoip:ru`, и проверить значения на опечатки. Панель отличает «нет такой категории», «нет такого атрибута», «не тот тип базы» и «файла базы нет — добавьте его в разделе гео-баз».
- Исправления: одна отравленная DNS-запись больше не блокирует проверку outbound'ов; при смене IP у WARP **сохраняется лицензионный ключ Plus**; ошибки запроса allocation больше не теряются; настройки salamander корректно импортируются из стандартных параметров obfs; «неограниченный» freedom-outbound в базе ужесточён.

### Изменения в разделе 12 — Узлы (мультипанель, master/slave)

- **Клонирование inbound'ов на узлы** (первая реализация): выбранные inbound'ы разворачиваются на несколько узлов разом, с отчётом «сколько клонировано / сколько не вышло».
- **Токен API узла можно шифровать в состоянии покоя** (опционально) — в базе не остаётся читаемого токена.
- Синхронизация стала аккуратнее: **уже развёрнутый совпадающий inbound усыновляется, а не пересоздаётся**; выключенные inbound'ы, о которых снимок узла не может сообщить, **сохраняются**; устаревшая синхронизация сроков **больше не отменяет продления клиентов**; удаление клиентов, которых синхронизация удалять не собиралась, исправлено; отметка об усыновлении не ставится, если усыновлять было нечего.
- **mTLS:** проверяется **каждый** сертификат в доверенном наборе узлов; ротация мастер-сертификата применяется **без перезапуска панели** (кнопка «Reload master mTLS credential», `POST /panel/api/nodes/mtls/reloadClient`); мастер-учётные данные пишутся атомарно, тихая перевыдача исключена.
- Ошибки сохранения heartbeat'а и удаление inbound'а по снимку узла теперь **попадают в лог**, а не теряются.

### Изменения в разделе 13 — Настройки панели

- **Белый список для лимита IP** («IP limit allowlist»): адреса и подсети (через запятую, IP или CIDR), которые лимит **никогда не учитывает и никогда не банит**. Общий офисный или кампусный адрес больше не съедает лимит клиента.
- **Импорт базы сохраняет настройки этой машины** — новый флажок «Keep this machine's settings» (включён по умолчанию): адреса и порты прослушивания, базовый путь, пути к сертификатам и идентичность узла берутся у текущей панели, а не из загруженного файла. Снимите флажок, чтобы вернуть прежнее поведение — полный клон файла.
- Календарь: подписи локализованы, добавлен выбор **григорианского / джалали**; кнопка очистки даты в джалали-календаре теперь действительно очищает поле.
- Исправления: при неубедительном результате проверки fail2ban **лимиты IP сохраняются**, а не сбрасываются; авто-удаление LDAP **не вычищает всех клиентов**, если каталог вернул пустой ответ; при пустой настройке в базе используется секрет по умолчанию.

### Изменения в разделе 14 — Telegram-бот

- Длинные сообщения **разбиваются по границам строк**, а не по символам — таблицы и списки больше не рвутся посередине.

### Изменения в разделе 15 — Гео-базы (geoip / geosite и кастомные)

- Появился **просмотр содержимого гео-баз**: список файлов в папке Xray с числом категорий, размером и датой обновления; список категорий; постраничный просмотр записей и подсетей; проверка набора значений против базы. Эндпоинты — `GET /panel/api/xray/geodata/files`, `/categories`, `/entries` и `POST /panel/api/xray/geodata/validate`.

### Изменения в разделе 16 — Эксплуатация: бэкапы, логи, обновление, CLI

- **Перед обновлением на 3.7.0 сделайте бэкап базы** — при первом запуске выполняются миграции схемы (см. раздел 1).
- Импорт базы по умолчанию **не перетирает сетевые настройки этой машины** (см. раздел 13).
- `x-ui setting -getApiToken` ротирует единственный токен `cli-fallback` (см. раздел 2).
- Собственные файлы в `bin/` переживают обновление; `update.sh` ходит через прокси панели.
- Наполовину применённая стартовая миграция **больше не может зафиксироваться молча** — панель не поднимется с полусломанной схемой вместо того, чтобы делать вид, что всё в порядке.
